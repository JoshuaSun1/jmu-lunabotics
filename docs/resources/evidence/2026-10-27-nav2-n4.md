# Nav2 Stage N4 static-only costmap evidence — 2026-10-27

## Scope and safety boundary

N4 adds lifecycle-managed global and rolling local costmaps for the explicitly
authorized AprilTag-only development profile. It starts no planner,
controller, behavior tree, navigation action, velocity smoother, final
`/cmd_vel`, hardware interface, or motor output. Physical use is prohibited.

The profile requires three explicit launch choices:

```text
enable_costmaps:=true
enable_development_tf:=true
allow_test_only_tf:=true
```

It rejects production-EKF coexistence and any localization profile other than
`apriltag_development_only`. The costmaps consume N3 TF but do not authorize
motion. Localization loss stops new N3 TF and the existing command gate blocks
nonzero commands after the `0.50 s` development freshness interval.

## Configuration under test

| Property | Global costmap | Local costmap | Provenance |
|---|---:|---:|---|
| Frame | `map` | `odom` | Project frame contract |
| Resolution | 0.05 m/cell | 0.05 m/cell | Team-approved development value |
| Dimensions | Arena map, 139 x 102 cells | 4.0 x 4.0 m, 80 x 80 cells | Map artifact / team-approved development value |
| Update/publish | 1/1 Hz | 5/2 Hz | Untuned development starting values |
| Footprint | 1.10 x 0.60 m centered polygon | Same | Team estimate; unmeasured |
| Footprint padding | 0.0 m | 0.0 m | Provisional; not a safety margin |
| Layers | Static, inflation | Static, inflation | N4 static-only decision |
| Inflation | 0.45 m, factor 3.0 | Same | Team-approved, experimentally untuned |
| TF tolerance/initial timeout | 0.50/2.0 s | Same | Development-only timing values |

There is deliberately no obstacle or voxel plugin. Rocks, craters, other
robots, terrain changes, the unresolved column, and unmodeled robot geometry
are invisible. Arena-scene markers remain visualization-only and are not
costmap input.

## Artifacts

- `lb_navigation/config/nav2_n4_costmaps_development.yaml` owns the map server,
  costmap, layer, footprint, timing, and lifecycle parameters.
- `lb_navigation/launch/nav2_n4_costmaps.launch.py` composes N3, the map
  server, two standalone costmap lifecycle nodes, lifecycle manager, optional
  arena markers, and optional RViz.
- `lb_navigation/rviz/nav2_n4_costmaps.rviz` displays the static map, global
  and local grids, both footprints, fused pose, TF, and arena markers.
- `lb_navigation/test/test_nav2_n4_costmaps.py` checks configuration, map
  geometry, inflation, lifecycle order, RViz, opt-ins, and absence of motion
  components.
- `lb_navigation/test/test_nav2_n4_lifecycle_runtime.py` supplies a current
  synthetic test pose and checks active lifecycle state plus published costmap
  geometry when the declared runtime packages exist.

Official Navigation2 source was checked to confirm that
`nav2_costmap_2d` is the standalone executable and that the node publishes
relative `costmap` and `published_footprint` interfaces from its namespace.

## Known limitations and remaining work

- The robot footprint, zero padding, inflation, rates, and tolerances are not
  measured or experimentally tuned.
- N3 localization is intermittent and AprilTag-only; there is no velocity or
  wheel/IMU propagation.
- Costmaps may remain lifecycle-active and retain old data after TF loss;
  command authorization remains locked independently.
- Static occupied cells and inflation are structurally tested, but live
  collision queries and visual appearance await runtime packages.
- CPU, memory, update latency, missed cycles, TF jitter, and endurance were
  not measured.
- N5 must add planning/control only to mock output and preserve all N3/N4
  fail-closed boundaries.
