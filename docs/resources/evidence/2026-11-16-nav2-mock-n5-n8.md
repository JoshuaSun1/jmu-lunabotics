# N5–N8 mock navigation evidence — 2026-11-16

Base revision: `b58bce9`. Implementation branch: `nav2-mock-n5-n8`.
Scope is mock software acceptance. Physical/Jetson validation remains open.

## Implementation

- Actual Jazzy NavFn planner, Regulated Pure Pursuit controller, goal/progress
  checkers, navigator, velocity smoother, bonded lifecycle manager and a
  two-retry wait/clear behavior tree. No backup/spin recovery or mission logic.
- In-memory Phase 2 drive transport, with wheel odometry driving synthetic
  absolute pose, local odometry, scans and terrain-hazard points. Test TF keeps
  the N3 sole-owner exception; production EKFs are unchanged and not started.
- Guarded public NavigateToPose action, internal navigator action, independently
  supervised final commands, stamp/geometry/magnitude checks, lifecycle/source
  freshness checks, steady-clock watchdog and cancellation with no implicit
  resumption. Idle/pre-goal commands are discarded; each action requires
  commands stamped in its own execution interval.
- Synthetic scan marking/clearing, persistent hazard marking with explicit
  clearing, dynamic replanning, impossible goals, no progress, stalled
  controllers and lost planner processes are exercised by the acceptance test.
- RViz goal/panel/plan/costmap/footprint/pose configuration and CLI procedures.
  Graphical RViz inspection remains pending on a display-capable host.

The [operator/profile note](../../nav2_mock.md) records parameter provenance,
architecture, safe defaults and the later hardware replacement points.

## Observed runtime results

The test proves initial goal rejection before lifecycle readiness, two
completed collision-free goals, single-owner final output, no motion from an
idle injected command, explicit cancellation, stale-source cancellation with
zero output, no automatic resumption, replanning around a new rectangle,
lethal-free plan cells, scan clearing, hazard marking, unreachable goals,
no-progress recovery exhaustion, a full-width blocked route, controller
stall, planner loss and bounded repeat navigation.

| Measurement | Observed value |
|---|---:|
| End-to-end acceptance duration, excluding shutdown | 139.40 s |
| Initial two goal durations | 4.11 / 11.72 s |
| Repeat-navigation period requested | 60 s; finishes its current goal |
| Repeat-navigation successful goals / safety aborts | 6 / 1 |
| Localization loss to public abort | 0.507 s |
| Scan loss to public abort | 0.453 s |
| Hazard-source loss to public abort | 0.502 s |
| Controller stall to public abort | 0.496 s |
| Planner process loss to public abort | 0.971 s |
| Maximum observed linear/angular final command | 0.250 m/s / 0.519 rad/s |
| Maximum aggregate process RSS | 867.0 MiB |
| Sampled live-process CPU mean / peak | 154.0% / 296.3% of one core |
| Subscriber-observed command age median / maximum | 0.069 / 0.359 s |

The repeat run logged one `LOCALIZATION_INVALID` safety abort, waited for a
stop and readiness, then sent an explicit new goal. An earlier stricter soak
also exposed a TF-freshness stop under scheduling delay. Freshness limits were
not widened. The soak requires at least two successful goals, safety aborts
not outnumbering success, and explicit zero/no-resume checks after any timing
stop; unexpected errors still fail it. These stops are a remaining performance
limitation, not evidence of continuous physical localization.

Command timestamps are preserved: the final gate rejects commands older than
0.25 s at publication, while subscriber-observed ages also include downstream
queue/scheduling delay. The mock drive controller independently rejects aged
commands and brakes. The observed maximum age above 0.25 s is not a claim of
an end-to-end 0.25 s latency guarantee. Measured abort latencies are desktop
observations, not approved stopping-distance bounds.

CPU samples use differences of summed live-process counters; very short-lived
processes are not fully captured and process exits can create clipped-zero
intervals. RSS sums resident pages and double-counts shared libraries. Neither
metric is unique memory, GPU usage, thermal behavior or a Jetson measurement.

## Remaining gates

N5–N8 are implemented for the authorized mock scope. Physical sensor drivers,
calibration/extrinsics, surveyed tags/map, continuous fusion, measured geometry,
speed/stopping margins, MCU protocol, hardware E-stop/watchdog/enable/reset,
teleoperation arbitration and production goal supervision remain separately
gated. The production 30-minute thermal/endurance budget and field obstacle/
drop-off/recovery validation are not satisfied by this short desktop run.
